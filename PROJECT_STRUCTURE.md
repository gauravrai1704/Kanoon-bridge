# Kanoon-Bridge — Project Structure

Legal search across the IPC→BNS change, with Hinglish queries and jurisdiction/temporal facets.
Owners: **A** = indexing, **B** = version normalisation, **C** = Hindi/Hinglish, **D** = ranking + evaluation.

## Root files

| File | What it does |
| --- | --- |
| `README.md` | Setup, how to run, data sources and credits, what works, what is planned. Graders reproduce the demo from this alone. |
| `requirements.txt` | Pinned Python dependencies (`rank_bm25` is **not** used — BM25F is our own code; see `rank/bm25f.py`). |
| `pyproject.toml` | Makes `src/kanoon_bridge` installable with `pip install -e .`, so imports work everywhere. |
| `Makefile` | One-word commands: `make data`, `make index`, `make eval`, `make app`, `make test`. Runs the `scripts/` in order. |
| `.gitignore` | Excludes `data/raw`, `data/processed`, `results/runs`, model weights, `.env`. |

## `configs/`

| File | What it does |
| --- | --- |
| `default.yaml` | All tunable values in one place: BM25 `k1`/`b`, zone weights, λ for authority, binding/persuasive weights, tier cut-offs, top-K, model names, file paths. No magic numbers in code. |
| `eval.yaml` | Which test sets, systems and ablation steps to run; k values for P@k; output paths. |

## `data/` (data files, not code)

| Path | What it holds |
| --- | --- |
| `raw/` | Downloads as received: IL-PCSR, BNS bare-act text, crosswalk PDF. Never edited. |
| `processed/` | Our cleaned corpus (`docs.jsonl`), built indexes, embeddings, citation graph. Regenerated by scripts. |
| `crosswalk/ipc_bns.csv` | One row per mapping: `ipc_section, bns_section, relation (same/split/merge/new/dropped), note`. Built by `parse_crosswalk.py`, then hand-checked. |
| `crosswalk/offence_ids.csv` | Canonical offence IDs, e.g. `OFF_MURDER`, and the IPC and BNS sections that map to each. The core of normalisation. |
| `lexicons/hinglish_legal_terms.csv` | Romanised and Devanagari forms of legal terms → English term (`hatya, हत्या → murder`). |
| `lexicons/*_stopwords.txt` | Hindi stop words; legal boilerplate words ("hon'ble", "learned counsel") removed before scoring. |
| `lexicons/court_to_states.csv` | Each court → the states/UTs under its jurisdiction. Supreme Court → all. |
| `queries/*.jsonl` | Hand-written test queries, one JSON per line: `id, text, lang, state, incident_date, notes`. |
| `queries/qrels/` | Relevance judgments per test set: `query_id, doc_id, grade, judge`. |

## `src/kanoon_bridge/` — core package

### Shared

| File | Owner | What it does |
| --- | --- | --- |
| `config.py` | D | Loads `configs/*.yaml` into a typed object. Every module reads settings from here. |
| `schema.py` | A | Shared data classes everyone imports: `Document` (id, type, court, states, date, code, zones, statutes cited), `Query` (text, lang, state, incident_date), `Posting`, `ScoredDoc`. **Agree on this first, in hour 1.** |
| `search.py` | D | The single entry point: `search(query) → ranked statutes + precedents`. Runs analyzer → statute bridge → precedent ranking → fusion → authority → top-K. The CLI, the app and the evaluator all call this. |

### `ingest/` — turning raw data into documents (owner A, crosswalk B)

| File | What it does |
| --- | --- |
| `load_ilpcsr.py` | Reads IL-PCSR queries, precedents, statutes and qrels; returns `Document` objects and the official train/val/test splits. |
| `load_statutes.py` | Reads BNS bare-act text; splits it into one `Document` per section with title and text. |
| `parse_crosswalk.py` | Extracts the IPC↔BNS table from the government PDF into `ipc_bns.csv`; marks split/merge/dropped rows. **(B)** |
| `segment.py` | Splits each judgment into zones (facts, arguments, ratio, decision) using IL-PCSR role labels if present, else cue-phrase rules. Splits statutes into sub-sections. This is the "what is a document" decision. |
| `metadata.py` | Pulls court name and decision date from judgment headers; maps court → states via `court_to_states.csv`; sets the code in force (IPC or BNS) from the date. Feeds the facets. |

### `text/` — analysis and normalisation (owners B and C)

| File | Owner | What it does |
| --- | --- | --- |
| `pipeline.py` | all | **The one text pipeline** for documents and queries: tokenize → stop words → stem → collision → version normalisation. Unfinished steps are skipped with a warning so the system runs end to end early. |
| `tokenize.py` | A | Legal-aware tokeniser: case folding, keeps section tokens intact (`302`, `304A`, `498A`, `s.302`, `Section 302 IPC` → one section token with its code). |
| `stem.py` | C | Porter stemmer for English; light suffix stripper for Hindi; a switch to turn stemming off for the ablation. |
| `version_norm.py` | B | **Core novelty.** Maps every section token to its canonical offence ID using `offence_ids.csv`, at index time and query time. Handles split/merge as weighted many-to-many mappings. |
| `collision.py` | B | Resolves bare numbers like "302" that mean different offences in IPC and BNS. Uses an explicit code word, the incident or judgment date, and nearby offence words; returns candidate readings with confidence. |
| `transliterate.py` | C | Converts Devanagari ↔ Roman and normalises Hinglish spelling (merge aspirated forms, collapse doubled vowels) before lookup in the legal-term lexicon. |
| `phonetic.py` | C | Soundex-style codes tuned for Romanised Hindi, so `hatya / hathya / hattya` match. Used for query-side term matching. |

### `index/` — data structures (owner A, tiers D)

| File | Owner | What it does |
| --- | --- | --- |
| `positional.py` | A | Inverted index: term → postings of (doc id, positions). Supports phrase queries. Skip pointers optional. |
| `zones.py` | A | One posting list per (term, zone), so scoring can weight the ratio zone differently from facts. Feeds BM25F. |
| `facets.py` | A | Parametric index for spatio-temporal filters: state, court, decision date range, code (IPC/BNS), sections cited. Returns doc-id sets for fast Boolean filtering. |
| `tiers.py` | D | Tiered index (tier 1 = high-authority precedents) and per-term champion lists. Used for the efficiency comparison. |
| `store.py` | A | Saves and loads all indexes to `data/processed/` (pickle or JSON), so the app starts instantly. |

### `query/` — understanding the user's input (owner A, analyzer C)

| File | Owner | What it does |
| --- | --- | --- |
| `parser.py` | A | Parses query syntax: free text, quoted phrases, AND/OR/NOT, `/k` proximity, filters like `state:delhi`, `date:2025-03-01`, `code:bns`. Produces a query tree. |
| `boolean.py` | A | Executes AND/OR/NOT over postings; intersects in increasing document-frequency order. |
| `proximity.py` | A | Westlaw-style `term1 /k term2` matching using positions. |
| `analyzer.py` | C | Runs the same pipeline on the query as on documents: detect language → transliterate → phonetic and lexicon expansion → tokenize → version normalisation → collision resolution. Shows each rewritten form (for the video). |

### `rank/` — scoring (owner D, dense C)

| File | Owner | What it does |
| --- | --- | --- |
| `vsm.py` | D | tf-idf with lnc.ltc weighting and cosine similarity. The classic baseline. |
| `bm25f.py` | D | BM25 with per-zone weights (BM25F). Main lexical scorer. |
| `dense.py` | C | Encodes zone paragraphs with NLLB-E5 (or a multilingual fallback); scores a query by max similarity over a document's paragraphs. Loads pre-computed embeddings. |
| `statute_bridge.py` | D | Retrieves top statutes for the query, then uses them to filter and expand the precedent query (precedents citing those statutes get a boost). Our replacement for IL-PCSR's LLM cross-task step. |
| `citation_graph.py` | D | Builds the citation graph from train-split qrels and precedent texts (never test qrels). Splits it into jurisdiction subgraphs. |
| `authority.py` | D | Static quality g(d): PageRank on the graph, combined per jurisdiction. Computes g(d \| state): full weight for Supreme Court and the user's own High Court, reduced weight for other High Courts. |
| `qpp.py` | D | Query performance predictors with no labels: max-idf, average idf, score gap between rank 1 and 2, query clarity. Used by fusion and by RAG abstention. |
| `fusion.py` | C | Combines lexical and dense scores (normalised); the weight α is set per query from QPP signals. |
| `topk.py` | D | Heap-based top-K selection and the final net score: relevance + λ·g(d \| state). |

### `rag/` — additional work, only after the hour-26 gate

| File | What it does |
| --- | --- |
| `chunker.py` | Turns top-ranked statutes and zone paragraphs into numbered chunks for the prompt. |
| `generate.py` | Calls the LLM with the chunks; requires one chunk citation per sentence. Keeps the API key in `.env`. |
| `citation_check.py` | Re-scores each generated sentence against its cited chunk with tf-idf cosine; flags sentences below the threshold. |
| `version_check.py` | Uses `version_norm` and `collision` to flag wrong-code citations (IPC for a post-July-2024 offence) and bare colliding numbers. |
| `abstain.py` | Uses `qpp.py` signals to return "not enough grounding" instead of an answer when retrieval looks weak. |

### `eval/` — measuring everything (owner D)

| File | What it does |
| --- | --- |
| `metrics.py` | Precision, recall, P@k, R@k, MAP, MRR, nDCG, and IL-PCSR's macro-F1@k (k chosen on validation). |
| `qrels.py` | Loads relevance judgments for IL-PCSR and our hand-built sets; builds the rule-based binding/persuasive grades for E6. |
| `run_eval.py` | Runs a named system on a named test set and saves the ranked run to `results/runs/`. |
| `ablation.py` | Runs the ablation ladder (BM25 → +zones → +bridge → +g(d) → +dense → +QPP-α → +g(d \| state)) and the language ablation. |
| `efficiency.py` | Times exhaustive vs tiered vs champion-list scoring; records latency and Recall@20. |
| `agreement.py` | Inter-judge agreement on hand-judged sets (percent agreement and Cohen's kappa). |
| `plots.py` | Produces the report and video charts into `results/figures/`. |

| File | What it does |

## `tests/`

`conftest.py` provides `@todo`: a test for a stub that still raises `NotImplementedError` is skipped, and runs for real once the code exists — `make test` stays green and tells you when you're done. `test_schema_and_pipeline.py` covers the shared plumbing. Other unit tests (`pytest`) cover the parts most likely to break silently: tokenising section numbers, crosswalk mappings, collision resolution, phonetic codes, positional and Boolean queries, BM25F on a toy corpus, authority weighting, and metric formulas on hand-computed examples.

## Integration rules for the team

1. **Agree on `schema.py` in hour 1.** Every module passes `Document`, `Query` and `ScoredDoc` objects, nothing ad hoc.
2. **One analyzer for both sides.** Documents and queries go through the same `text/` pipeline, or normalisation breaks.
3. **No test leakage.** `citation_graph.py` and anything learned or tuned use train/val only.
4. **Everything through `search.py`.** The app and the evaluator must call the same function, so demo results equal reported results.
5. **Log AI use as you go** in `docs/ai_use.md`.
